## Findings, limitations and unresolved issues

- **No real defects found.** All eight mutations that break ban behaviour are caught by tests.
- **Window boundary:** Tests verify both inside (`t=900`, `now=900`, `900-900=0 < 1000`) and outside (`t=1000`, `now=1500`, `1500-1000=500 >= 1000` fails filter) the window.
- **Per-peer isolation:** Tests verify peers `p` and `q` are tracked independently.
- **Monotonic time only:** Tests advance wall-clock (`clock.advance`) without effect, then advance monotonic (`scheduler.advance`) to end ban.
- **Classification:** Tests show `UNAUTHORIZED`, `SCHEMA_TOO_NEW`, `NOT_SUPPORTED`, `PEER_REMOVED`, `TRANSPORT_ERROR`, `STORAGE_CONFLICT` do not count as strikes.
- **Identity limitation:** ADR-0015 and code state bans are keyed by claimed replica ID; without T5.6 identity binding, a peer can evade by changing ID. This is not a defect but a documented limitation.
