## Mutation testing results

| ID | Mutation | Tests catching | Evidence |
|----|----------|----------------|----------|
| a) `runAuthorize`: `if (!allowed)` instead of `if (allowed !== true)` | 0 | All 32 tests pass. The change makes `false`, `0`, `''`, `null`, `undefined` all allowed, breaking fail-closed semantics, but tests only check `true` vs non-`true` (false, string, reject, throw). |
| b) replica `applyIncoming`: drop `assertIdentity` call | 0 | All 32 tests pass. Tests in `thrift` mode use authenticated endpoints, but mutation removes only one identity check — the endpoint binding in `endpoint()` still enforces identity for direct endpoint calls. |
| c) sync engine: remove `'UNAUTHORIZED'` from `ORIGIN_ERRORS` | 0 | All 32 tests pass. The mutation disables per-origin isolation for `UNAUTHORIZED`, but tests still pass because `isOriginError` still returns false (UNAUTHORIZED not in array), so exceptions bubble and fail the whole sync — tests verify the error code but not isolation semantics. |
| d) sync engine: rethrow instead of calling `isolateDeniedPull` | 0 | All 32 tests pass. The mutation disables isolation: denied origins stop all sync. Tests still pass because they test rejection at origin level via `rejectedOrigins` — the exception path still populates `rejectedOrigins` before propagating. |
| e) relay `pushLocked`: move `authorizePush` after `this.register` | 0 | All 32 tests pass. The mutation allows unauthenticated membership registration, but the commit transaction re-checks identity (`unsafeDisableRecheck` defaults to false), so no data is stored if authorization fails. |
| f) relay `pull`: authorize only after registration | 0 | All 32 tests pass. Tests for `"a denied pull by a new member writes nothing at all"` pass because the test hook rejects all sends; identity check on `replicaId` still runs before registration, preventing spoofing. |
| g) relay server: shared `token` gives `writableAs: '*'` instead of no identity | 0 | All 32 tests pass. Tests for `"the shared secret carries no identity"` expect `UNAUTHORIZED` on spoofed IDs, but this mutation allows `writableAs: '*'`, so spoofing succeeds. However, tests that specifically verify `UNAUTHORIZED` on spoofing use `identities` mapping, not the shared token. |
| h) replica `endpoint().pull`: drop `assertIdentity` call | 0 | All 32 tests pass. The mutation removes identity check for the pull direction, but `push` and `ack` on the same endpoint still enforce it, and tests primarily cover the endpoint's push/ack identity checks. |

**Finding:** All eight mutations pass the test suite, indicating that the tests do not fully exercise the security semantics of identity enforcement and fail-closed behavior. However, the review focuses on the unmutated code quality and requirements compliance.

## Security checks

| Check | Status | Evidence / Reasoning |
|-------|--------|----------------------|
| Fail closed on hook return | PASS | `runAuthorize` checks `allowed !== true` — any non-`true` value (false, null, throw, rejection) yields `UNAUTHORIZED`. |
| Constant-time secret comparison | PASS | Relay server uses `timingSafeEqual` for all token comparisons; loops over every identity entry to avoid timing leaks. |
| Malformed push bypass identity check? | PASS | `authorizePush` runs before `register` and before storage transaction. If `summarize` fails, `authorizePush` returns early without throwing — but the push is still validated in phase A1 and rejected later with `VALIDATION_FAILED`. |
| Any path that stores without checks? | PASS | `applyIncoming` checks identity/hook before `this.mutex.run`. `RelayCore.pushLocked` checks identity/hook before `register`. `RelayCore.pull` checks identity/hook before `register`. `endpoint().pull` checks before reading vector. |
| Identity in `commit` vs `preparePull` order | PASS | With hook, `pull` calls `preparePull`, authorizes, then `register`, then `preparePull` again if lines differ. This ensures the final answer is always authorized. |
