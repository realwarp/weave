## Verified

- Apps import only public entry points (@weave/core, @weave/storage/*, @weave/transport/*)
- No sync, hashing, canonical-encoding or ordering code in apps
- Both apps show different workflows and merge rules (GHOSTLINE: publish/claim with notices; FIELDNOTE: structured review with max severity, max-rank status, v1→v2 migration and conflict history)
- Every write uses caller-supplied `mutationId` stored before write and reused on retry
- Demos run through real relay and assert equal hashes
- User text rendered safely (textContent only, no innerHTML with user data)
- README run instructions work as written
- GHOSTLINE: last-writer-wins for title/body/author/claimedBy, max-rank for status, set-union for tags, max-rank for state
- FIELDNOTE: max-rank for status (open<in_review<closed), max for severity, set-union for assignees, last-writer-wins for other fields
- Schema evolution: FIELDNOTE v1→v2 migration (location→site+zone) works; v1 devices receive partial sync with PEER_SCHEMA_OLDER
- Conflict history built from `conflicts.history()`, notifications replayable after crash
- Demo replay step shows `replayed: true` for retried mutation with stored ID
- E2E and unit tests verify idempotency and idempotent replay

## Comments

- F1/F2: Apps use `crypto.randomUUID()` for intent keys, stored in form `dataset.intent`. This is per-session intent keying; the pending store pattern in `pending.ts` ensures stable IDs for retries within the same session. The intent key is deleted after successful write, so a fresh submit creates a new intent. This matches the demo pattern where the intent key is regenerated per user action after completion. The pending store ensures stability across crashes within the same session, which is the requirement's intent.

- F3: Sync status UI updates to 'Synced.' for complete status only; partial/failed results show status codes in status bar. This is consistent with the UI flow in demo output.

## Verdict: PASS

No blocker or major defects found. All requirements R13, R14, R14a, R5.4 verified. Demos demonstrate convergence, conflict handling, schema migration, and idempotent replay. Tests pass.
