## Boundary analysis

The approved spec (R10.5, T5.7) does not define boundary inclusivity. ADR-0015 records the decision:

> **Window boundary.** R10.5 and the T5.7 task do not define whether the window edge is inclusive. Decision: a strike counts while it is less than `windowMs` old (`now - t < windowMs`); a strike exactly `windowMs` old no longer counts. So "3 strikes within 60 s" means three strikes whose first and last are less than 60 s apart.

The test in `packages/core/test/sync/ban.test.ts` pins these three cases:

```typescript
expect(counts(W + 1)).toBe(false); // N - W - 1: outside
expect(counts(W)).toBe(false); // N - W: exactly windowMs old, no longer counts
expect(counts(W - 1)).toBe(true); // N - W + 1: inside
```

- **N-W-1 (age W+1)**: strike is `W+1` ms old, filter `now - t < windowMs` excludes it (output `false`) — correct.
- **N-W (age W)**: strike is exactly `W` ms old, filter excludes it because `W < W` is false (output `false`) — matches ADR-0015.
- **N-W+1 (age W-1)**: strike is `W-1` ms old, filter includes it because `W-1 < W` is true (output `true`) — correct.

Mutation **b** (`t <= now`) makes every strike pass the filter (always counts), breaking the window entirely.

Mutation **i** (`<=` instead of `<`) makes the exact boundary (`N-W`) count as inside, so `counts(W)` returns `true`, violating ADR-0015.
