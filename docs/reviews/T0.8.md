#### SyncResult Discriminated Union Validation

The `SyncResult` type correctly implements the discriminated union with proper constraints:

1. **`complete` status:** `blocked: readonly []`, `rejectedOrigins: readonly []`, includes `settled: VersionVector`
2. **`partial` with `PEER_SCHEMA_OLDER`:** `blocked: readonly [BlockedOrigin, ...BlockedOrigin[]]` (array with at least one element)
3. **`partial` with `NOT_SETTLED`:** `blocked: readonly []`, includes `endpoint` and `local` version vectors
4. **`failed` status:** includes `code: ErrorCode`, `error: WeaveError`, and both `blocked` and `rejectedOrigins`

Type tests in `packages/core/test/api/contracts.test.ts` verify all three partial cases with correct constraints.

#### Type-Level Tests Verified

Tests confirm:
- `mutationId` is required on `create`, `update`, `delete` (compile-time error without it)
- `collection.history(recordId)` is available on Collection interface
- `conflicts.current()` and `conflicts.history()` are available on Replica
- Storage key helpers (`keys.op()`, `keys.pend()`, etc.) and `padSeq()` work correctly

### ✅ Canonical Vectors (T0.4, D7, RFC 8785)

Vectors in `packages/core/test/canonical/vectors.json` include:

1. **RFC 8785 official examples** (with 1e30 marked unsupported for WEAVE values)
2. **UTF-16 vs UTF-8 property order** (`U+E000` vs `U+10000` - canonical JSON sorts by UTF-16, so `U+10000` < `U+E000`)
3. **Negative zero** (`-0` → `0`)
4. **Numbers** including `0.1`, `100`, `1e-7`, safe integers, `0.30000000000000004`
5. **Nested and empty containers**
6. **String escapes** (control characters, quotes, backslashes)
7. **Non-ASCII strings not normalized** (precomposed vs decomposed)
8. **Op payload example** (complete D2 payload for hashing)
9. **Set-union output** sorted by UTF-8 bytes of canonical encoding

A reference implementation in `tests/canonical-reference/` cross-verifies every vector.

## No Contradictions Found

After reading `requirements.md` D1-D8 and comparing with implementation:

- ✅ **D1**: Op identity `(replicaId, seq)`, contiguous seq per replica, pending buffer separate
- ✅ **D2**: Complete op payload with `hash` over canonical encoding
- ✅ **D3**: Causal order via context, concurrent detection via mutual exclusion
- ✅ **D4**: Total order `(lamport, replicaId, seq)` with UTF-8 byte comparison
- ✅ **D5**: State from frontier resolution
- ✅ **D6**: Delete wins in MVP
- ✅ **D7**: Canonical JSON per RFC 8785 with UTF-16 key order
- ✅ **D8**: Conflict view and history log with `conflictHistoryIds` storage

The accepted-vs-pending op distinction is correctly implemented:
- `pendingBuffer` counts buffered ops only (not accepted)
- `pendingOps` per peer counts accepted ops not yet acknowledged
- `lamport` and `context` computed from accepted ops only
- Promoted ops move atomically from `pend/` to `op/` with one transaction
