## Coordinator check of a statement the reviewer removed

In `RelayCore.pushLocked` the order is: the op-count limit, then `authorizePush`, then `register`,
then `verifyOpLine`. `authorizePush` always runs the claimed-`replicaId` identity check first. If
a line cannot be parsed, `summarize` fails, `authorizePush` returns without the per-origin check
and hook, and the later `verifyOpLine` rejects the whole push before any op or acknowledgement is
written. Membership is registered in that case only for a caller whose claimed ID passed the
identity check, which is the 0.1.0 behaviour for an invalid push.
