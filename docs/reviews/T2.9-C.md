# Review Report: T2.9-C Storage and Data

## Scope

File adapter (`packages/storage/src/file/`) and IndexedDB adapter (`packages/storage/src/indexeddb/`) review for:
- **R9**: Storage adapters contract
- **R10.4**: Crash safety of sync
- **R15.17**: File adapter corruption handling and recovery
- **R15.20**: Manual recovery procedure
- **Design 9.1**: File journal, locking, and recovery

**Tested components:**
- Journal format: 32-byte header (magic "WJ02", generation, epoch, txId, payloadLen, headerCheck), JSON payload, 32-byte SHA-256 trailer
- Lock mechanism: `LOCK` and `LOCK.recovery` files with hostId validation, nonce revalidation
- Recovery guard: Never removed automatically; manual offline procedure required
- IndexedDB: One `kv` store, Web Lock, strict durability transactions

## Findings

| ID | Severity | File:Line | Description | Requirement ID |
|---|---|---|---|---|
| F1 | Minor | format.ts:37-52 | `decodeHeader` returns `undefined` for incomplete header without distinguishing partial-header vs. other corruption; caller (`scanJournal.ts`) must infer | R15.17 |

**Verified:**
- Transaction atomicity: `OverlayTx` uses copy-on-write overlay; `commit` appends to journal atomically; journal sync precedes in-memory state update
- Scan order: `SortedStore` maintains keys in ascending byte order; `scanJournal` processes records in order
- 32-byte header: Magic "WJ02", generation/epoch u32, txId u64, payloadLen u32, headerCheck (first 8 bytes of SHA-256 over header without payloadLen+check), SHA-256 trailer over header+payload
- Auto-truncate: Only for incomplete final append (cut 32..len-1 bytes); partial headers (1..31 bytes) fail closed with `STORAGE_CORRUPT`
- Lock takeover: Only when holder provably dead (same reliable hostId, PID dead); nonce revalidation; guard (`LOCK.recovery`) present during recovery; never removed automatically; no override option
- IndexedDB: One `kv` store, per-call transactions, Web Lock, no await outside tx calls
