### File Journal Format (Design 9.1)

| ID | Severity | File | Description | Spec Reference |
|----|----------|------|-------------|----------------|
| J1 | NOTE | `packages/storage/src/file/format.ts:37-45` | Header check covers only first 8 bytes of SHA-256 | Design 9.1: "32-byte header with headerCheck" |

**Analysis:** `HEADER_BYTES = 32` is correct:
- Bytes 0-3: magic "WJ02"
- Bytes 4-7: generation (u32)
- Bytes 8-11: epoch (u32)
- Bytes 12-19: txId (u64)
- Bytes 20-23: payloadLen (u32)
- Bytes 24-31: headerCheck (first 8 bytes of SHA-256 over bytes 0-23)

The specification says "32-byte header with headerCheck", and this implementation is correct.

### Lock Takeover Rules (Design 9.1)

| ID | Severity | File | Description | Spec Reference |
|----|----------|------|-------------|----------------|
| L1 | NOTE | `packages/storage/src/file/lock.ts:197-242` | Lock takeover on Linux requires reliable hostId | Design 9.1: "Linux takeover" |

**Analysis:** `provablyDead` checks:
1. Both hosts have reliable hostId (`isReliable`)
2. Same hostname, bootId, pidNamespace
3. Process is dead (`isAlive(pid) === 'dead'`)

The `isReliable` function requires `hostname.length > 0 && !!bootId && !!pidNamespace`. On non-Linux platforms, `bootId` and `pidNamespace` are null, so takeover is refused.

This matches the design specification.
